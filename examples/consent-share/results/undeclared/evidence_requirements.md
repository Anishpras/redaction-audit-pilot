# Evidence requirements: Consent-based document sharing (pilot rule)

A completed share_document action is authorised if and only if a consent grant matches its document, recipient and purpose, the share happens at or after the grant and strictly before expiry, and no revocation is effective at or before the share. Expiry and revocation take effect at their recorded time.

A redacted log can be audited against this policy only if it keeps the evidence below. Each condition is listed with its *need type*; the guidance says which redaction forms preserve it. Generated by redaction_audit 1.2.0.

## document_matches (equality)

- **Rule:** `authority.document.id` equals `action.document.id`
- **What the log must keep:** Keep both values, or replace them with pseudonyms that stay consistent across every event (this also holds for 'different' rules such as four-eyes checks) the condition compares (scope run or global). Uniform masks remove the relation. Per-event pseudonyms remove it too, and if undeclared they turn every authorised action into a false alarm.
- **Tested views that keep it:** A_full, C_alias, C_no_expiry, C_no_revocation, E_pseudonym_run, F_pseudonym_global, G_times_bucket10, H_times_rank, I_purpose_masked
- **Tested views that lose it:** B_uniform_mask (unsafe), D_pseudonym_event (unsafe)

## at_or_after_grant (order)

- **Rule:** `authority.time <= action.time`
- **What the log must keep:** Keep the exact values (times, amounts, counts), or within-run ranks that preserve order and ties. Coarsened (bucketed) values leave boundary cases undecidable, and if undeclared they produce confident wrong verdicts.
- **Tested views that keep it:** none
- **Tested views that lose it:** A_full (untested), B_uniform_mask (untested), C_alias (untested), C_no_expiry (untested), C_no_revocation (untested), D_pseudonym_event (untested), E_pseudonym_run (untested), F_pseudonym_global (untested), G_times_bucket10 (untested), H_times_rank (untested), I_purpose_masked (untested)

## not_revoked (explicit_state)

- **Rule:** `authority.revocation.status` in ['not_revoked'] (violated by ['revoked'] when `authority.revocation.effective_at <= action.time`)
- **What the log must keep:** Record the state explicitly, including the 'clear' state (for example not_revoked), together with the time it took effect. A missing field must never stand for the clear state, because it cannot be told apart from redacted evidence.
- **Tested views that keep it:** A_full, B_uniform_mask, C_alias, C_no_expiry, D_pseudonym_event, E_pseudonym_run, F_pseudonym_global, H_times_rank, I_purpose_masked
- **Tested views that lose it:** C_no_revocation (unverifiable), G_times_bucket10 (unsafe)
